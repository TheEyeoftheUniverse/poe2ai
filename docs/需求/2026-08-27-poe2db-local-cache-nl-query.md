# poe2ai 一期需求：poe2db.tw 本地缓存 + 自然语言查询

> 范围: poe2ai 插件一期——把 https://poe2db.tw/ 的内容缓存到本地，用户用自然语言询问装备/词条时，由 LLM 主动调用工具查本地缓存作答。
> 目标:「让 AstrBot 帮我翻 wiki」。用户（仓库主人本人）就是最终用户。
> **用户约束（原话）:「我自己翻这个wiki是很费神的」——交互形态必须是自然语言直问直答，而不是让用户再学一套手动查询指令。**
> 数据源: https://poe2db.tw/（Path of Exile 2 社区数据库 wiki）

## 背景

用户玩 Path of Exile 2，日常需要查 poe2db.tw（装备基础数据、词条池等）。该站信息量大、页面密，人工翻阅费神。poe2ai 作为 AstrBot 插件，要把「翻 wiki」这件事交给聊天机器人：用户在聊天里随口问，机器人查数据、给答案。

## 需求清单（FR-1～FR-5 已定稿）

| # | 需求 | 来源（用户原话） |
|---|---|---|
| FR-1 | **本地缓存**：poe2db 数据存本地，查询默认只读本地，不请求网站 | 「最好是能把内容都存在本地」「不要让它每次都去翻」 |
| FR-2 | **按需更新**：本地查不到时才去 poe2db.tw 拉取，拉回后写入缓存，下次直接命中 | 「本地没有的才去这个网站里面更新数据」 |
| FR-3 | **装备查询**：按名称查装备（基础属性、需求等） | 「在我询问某个装备……的时候帮我翻阅存储在本地的wiki内容」 |
| FR-4 | **词条查询**：按词条（affix/mod）查数值区间、出现部位/物品类型等 | 「……或词条的时候」 |
| FR-5 | **自然语言主动调用**：注册为 LLM 工具（function calling），用户自然语言提问时模型自主决定调用并直接作答 | 「直接在我用自然语言问他的时候，它会主动调用工具去翻本地wiki，然后就能回答我」 |

### FR-5 补充说明（交互形态关键）

- 触发方式是 **LLM 自主调用**（AstrBot 的 `llm_tool` 机制），不是 `/指令` 触发。用户问「t1 攻速是多少」这类问题时机器人自己查、自己答。
- 手动指令可作为运维/调试补充（如强制刷新缓存），但不是用户主路径。

## 非功能约束

- NFR-1 **省人**：本插件存在的理由。回答要直接、结论化（数值区间、部位、结论），不要丢链接让用户自己看。
- NFR-2 **礼貌抓取**：poe2db.tw 是免费社区站、无官方 API。按需拉取要限频；不做全站高频爬取。
- NFR-3 **冷启动可用**：空缓存状态下问第一个问题也能答（走 FR-2 按需拉取）。

## 待定问题（实现前需拍板）

- Q1 **数据范围**：一期只做「装备 + 词条」两类按需缓存，还是启动时预抓常用页？站内技能/怪物/地图等其他数据用户未提，暂不做。
- Q2 **数据时效**：游戏大版本更新后词条池会变，而「本地没有才更新」意味着旧数据永不过期——是否需要手动/定期刷新机制？
- Q3 **语言**：poe2db 有中英双版（`/cn/` 路径）。默认抓哪版？是否中文提问答中文数据？
- Q4 **抓取粒度**：词条按物品类型分页分组、单页数据量大。按需拉取是「整类词条页一次拉全」还是「精确到单条词条」？

## 技术备注（方向参考，非决议）

- poe2db.tw 为纯静态站，数据内嵌在页面 HTML 中（页面自带 export 功能），无现成 JSON API；「更新数据」= 礼貌抓取页面 + 解析内嵌数据。
- 本地存储倾向 SQLite（词条数值区间查询友好），文件级 JSON 亦可，实现时定。
- AstrBot 侧用 `@filter.llm_tool` 注册工具，供宿主 LLM 在对话中自主调用。
